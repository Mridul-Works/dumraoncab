  password? link, footer "Trouble signing in? Ask the owner to reset

5. API & STORAGE (Node runtime; JSON files in data/ — gitignored)
---------------------------------------------------------------------
POST   /api/bookings          public — save a booking request
GET    /api/bookings          admin — list all bookings
PATCH  /api/bookings/[id]     admin — update status, note, cancel reason, driver/vendor
DELETE /api/bookings/[id]     admin — delete a booking
GET    /api/bookings/export   admin — download all bookings as CSV
GET    /admin/journal/export  admin — download Trip log entries as CSV
GET    /uploads/[file]        uploaded car photos (immutable cache)
GET    /admin/vendor-docs/[file] admin — private vendor documents (no cache)
Admin edits use Server Actions (app/admin/*actions.ts). Files:
bookings.json, fleet.json, fares.json, journal.json, uploads/. All
writes go through lib/db.ts: serialised per file and atomic (temp
file + rename); a corrupt file raises an error instead of reading as
empty. Fleet and fares fall back to the seeds in lib/site.ts until
first saved.
NOTE: JSON-file storage suits a VPS/Node host. On serverless
(Vercel etc.) swap lib/db.ts for a database first.

9. DRIVER APP (/driver — phone web app, noindex, robots-blocked)
---------------------------------------------------------------------
Design: Figma "Flow 10 · Driver app" (10.1–10.47) on Chinkara. A
390-wide phone layout (centred column on bigger screens). Pages in
app/driver/, parts in components/driver/ (ui.tsx, fields.tsx,
camera.tsx, Sheet.tsx, Trip.tsx …), actions in app/driver/actions.ts,
server helpers in lib/driverTrips.ts, sign-in in lib/driverAuth.ts.
Line art in public/driver-art/, icons from public/admin-icons/.
- Sign in (10.1–10.4): Welcome → mobile number → 6-digit code. Code
  is random, stored only as a hash with 10-min expiry
  (data/driver-otp.json); 3 wrong tries → new code needed; resend
  after 30 s, max 5 codes/hour per number; boxes turn red and clear
  on the next tap; Android WebOTP auto-fill. NO SMS provider: in
  development the code is printed to the server console and shown in
  a "Dev only" note; in production set DRIVER_OTP_WEBHOOK (POST
  {mobile, code}) or sign-in says "SMS is not set up". Session =
  HMAC-signed httpOnly cookie (30 days) keyed by
  DRIVER_SESSION_SECRET or data/driver-secret.key (auto-created).
- Join (10.5–10.11): photo, name, own car vs Dumraon Cab car, where
  you live, UPI → Aadhaar + licence (front and back stitched into one
  photo) → cars (stepper, car details, RC/insurance/permit/PUC, 4
  car photos) → check and submit. Draft kept in
  data/driver-drafts.json; Submit creates a Vendor (source
  "driver-app", status "pending") for /admin/vendors. Documents are
  private (lib/vendorDocs.ts → data/vendor-docs).
- Camera (10.7/10.8): live camera with guide box (getUserMedia),
  gallery pick, phone camera fallback (<input capture>); "Camera is
  off" screen with gallery option. Photos shrunk to 1600 px on the
  phone before upload.
- Office checks (10.12–10.15): Waiting for checking (documents
  grouped Verified / Being checked / Upload), Fix a document when
  staff ask for a re-upload, You are approved (once), Two quick
  settings (trip alerts, location, camera via browser prompts).
- Today (10.16–10.21, 10.47): greeting, Available switch (off duty
  keeps booked trips, hides new requests), week stats from the Trip
  log, next trip card, later trips, empty state, skeleton loading,
  checks for new trips every 20 s with a sound. Trips paused when a
  document has expired or the vendor is suspended.
