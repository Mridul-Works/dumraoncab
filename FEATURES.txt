4. ADMIN PANEL (/admin — noindex, robots-blocked, login required)
---------------------------------------------------------------------
Own shell: dark sidebar nav (horizontal scroll bar on mobile) with
live "new bookings" badge, signed-in email, View site, Log out.
- /admin/login: email + password. Works with no env setup (built-in
  password stored only as a scrypt hash; session key derived from
  the password at login, so the public repo can't be used to forge
  a session); ADMIN_EMAIL / ADMIN_PASSWORD / ADMIN_SESSION_SECRET env
  vars override. Server Action; HMAC-signed httpOnly session cookie
  (7 days, email + expiry, constant-time checks); failed attempts
  are slowed and keep the typed email; changing the password signs
  every session out. Every admin page,
  action and API re-checks the session.
- /admin (Dashboard): tiles for awaiting confirmation, received
  today, travelling today, trips in next 7 days, completed, all-time
  total (Indian time); "Needs confirmation" list with Call/WhatsApp
  buttons; "Upcoming trips" list; links to fleet/fares/content and
  the contact channels
- /admin/bookings: search (name, phone, place, car, notes), status
  filter tabs with counts, sort by received or travel date; status
  dropdown per booking; Details panel with customer notes, received/
  last-changed times, Call + WhatsApp (pre-filled confirmation
  message from lib/site.ts), internal note (saved), delete with
  confirm; "Log a booking" form for phone/WhatsApp trips (source
  "Phone"); Export CSV (Excel-safe, UTF-8)
- /admin/fleet: vehicles with photo, category, seats, specs, note,
  rate
- /admin/fares: routes (linked to public pages), per-km rates,
  hourly packages, fare notes
- /admin/content: contact & business details, services, testimonials
  (flagged as sample), FAQs
- Fleet/fares/content are read-only views; content is still edited
  in lib/site.ts

5. API (Node runtime; data in data/bookings.json — gitignored)
---------------------------------------------------------------------
POST   /api/bookings          public — save a booking request
GET    /api/bookings          admin — list all bookings
PATCH  /api/bookings/[id]     admin — update status and/or note
DELETE /api/bookings/[id]     admin — delete a booking
GET    /api/bookings/export   admin — download all bookings as CSV
Admin login/logout and panel edits use Server Actions
(app/admin/actions.ts). Store writes are serialised and atomic
(temp file + rename).
NOTE: JSON-file storage suits a VPS/Node host. On serverless
(Vercel etc.) swap lib/store.ts for a database first.
